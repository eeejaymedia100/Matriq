# SEO & Search Console — Runbook

Everything technical that can be hardened *in the repo* is already done
(see the 2026-09-02 progress-log entry). This page is the operational
checklist — what to verify in the console, and how to prove the setup works.
Most of it is still user actions on the VM/Cloudflare/Google because only
you can click those buttons.

## What's already in place (repo state)

| Concern | Implementation |
|---|---|

## One-time setup — Google Search Console (15 min, user action)

1. **Verify ownership of the domain** at [search.google.com/search-console](https://search.google.com/search-console):
   - Add property: **Domain** → enter `matriq.com.ng` (uses a DNS TXT record in Cloudflare — no HTML changes needed).
   - Or add a **URL-prefix** property `https://matriq.com.ng/` and (if you prefer the meta tag over DNS)
     paste Google's `<meta name="google-site-verification" content="…">` into `<head>` of `waitlist/index.html`
     — the exact spot is marked by the comment block above the JSON-LD script.
2. **Submit the sitemap:** Sitemaps → `https://matriq.com.ng/sitemap.xml`.
3. **Request indexing of the homepage:** URL inspection → `https://matriq.com.ng/` → *Request indexing*
   (a brand-new domain gets crawled on its own — this just speeds up the first pass).

## What to check 1–2 weeks after verification

- **Index coverage:** fewer than ~10 indexed pages is expected — the site is only 3 crawlable
  URLs; anything *more* (e.g. the legal pages duplicated under query strings) means canonicalization broke.
- **Page indexing → not indexed → crawled, currently not indexed:** fine as long as coverage is honest;
  **"Not found (404)"** entries mean a stale link somewhere — check the linked-from column.
- **Mobile usability:** any "text too small / clickable elements too close" warnings — the waitlist
  site uses fluid `clamp()` type and ≥44px touch targets, so there should be none.
- **Core Web Vitals in Search Console:** LCP/CLS under controls. The heavy 3D scene is now skipped
  on 2g/3g/saveData/small phones, so lab CWV should stay green with the CSS-orbs fallback.
- **sitemap.xml `lastmod`** — bump when the landing copy changes (weekly is fine).

## Proving the headers work (quick checks from the VM)

```bash
# Security + caching headers on the landing page
curl -sI https://matriq.com.ng/ | grep -i -E "strict-transport|content-security|x-frame|referrer|permissions|cache-control"
# Compressed transfer (zstd or gzip)
curl -sI -H "Accept-Encoding: gzip" https://matriq.com.ng/ | grep -i content-encoding
# Branded 404
curl -s -o /dev/null -w "%{http_code}\n" https://matriq.com.ng/does-not-exist
curl -s https://matriq.com.ng/does-not-exist | grep -o "<title>[^<]*</title>"
# Structured data present (expect Organization, WebSite, SoftwareApplication)
curl -s https://matriq.com.ng/ | grep -c "SoftwareApplication"
# Web app is noindex
curl -sI https://app.matriq.com.ng/ | grep -i x-robots-tag
```
